# Local reconstruction of the SuiteG6 codebase

The working tree is [engenharia/codebase-local](../engenharia/codebase-local/README.md). Open [SuiteG6.Local.code-workspace](../engenharia/codebase-local/SuiteG6.Local.code-workspace) for the complete recovered source navigation, or [SuiteG6.Verified.sln](../engenharia/codebase-local/SuiteG6.Verified.sln) for the verified editable components.

Result: **218 source projects, 22,126 C# files and 510 managed dependency names**. The verified solution built with native Framework MSBuild. The combined source build passed 19 Data.Core assertions and 16 original/rebuilt report-helper assertions; the report component compiles against the source-built sibling Data.Core, whose hash is recorded.

The broad extraction exports the current local vendor assemblies into per-assembly C# projects. Its exact counts, project paths and input identities are in [workspace-summary.json](../engenharia/codebase-local/workspace-summary.json), [PROJECTS.md](../engenharia/codebase-local/PROJECTS.md), [recovery-manifest.json](../engenharia/codebase-local/recovery-manifest.json) and [artifact-inventory.json](../engenharia/codebase-local/artifact-inventory.json). Project references are redirected to the local frozen managed snapshot rather than relying on the installation's paths. A file-hash index records the exported tree.

This recovers an inspectable local codebase, not the unavailable original source repository. Obfuscated names, missing comments, unrecovered native code and BAML resources retain their limitations. Decompiler export alone is not build verification. Six third-party dependency names have differing installed variants; the inventory records the deterministic selected origin and all alternatives.

## Using the local source

Run `python engenharia/codebase-local/tools/build_workspace.py` from the repository root. It compiles the verified components from their editable local files and runs their selected checks. It does not regenerate source. Individual scripts and project READMEs explain recovery and optional checks; logs and build manifests remain beside each project.

The toolchain is already installed: Python, Roslyn/.NET SDK and the native Windows Framework. No dependency downloads or new tools were installed. Framework references come from the installed Framework 4.8, rather than a pristine 4.6 targeting pack. A complete product launch is not provided because all-module source compilation and dependency/runtime integration are not established.

The workspace excludes configuration, credentials, customer data, backups and logs from acquisition. Recovered vendor source/binaries and build scratch remain local rather than being added to release packaging. No service, MongoDB database, installed application file or Insight financial calculation was modified.
